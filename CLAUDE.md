# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

`docs/PLAN.md` is the original brief (firstlight: one command turns a night's FITS frames into previews, linear stacks and an HTML report). Not yet built: GraXpert, plate solving, flats.

## Commands

```
python3.14 -m venv .venv && .venv/bin/pip install -e '.[dev]'    # system python3 is 3.9; need >=3.10
.venv/bin/pytest -q                                              # all tests (no Siril needed)
.venv/bin/pytest tests/test_scripts.py::test_align_script_single_filter_skips_registration
.venv/bin/firstlight <night-folder> -o <out> [--target NGC] [--filter H] [--dry-run] [--keep-intermediates] [--all-exposures] [--deconvolve] [--denoise] [--remove-stars] [--star-splitter classical|starnet] [--no-widget-enhance]
```

Siril comes from `brew install siril` (1.4.4; `siril-cli` on PATH, else `/Applications/Siril.app`). `--dry-run` writes and prints every generated script without running Siril. Siril prints a harmless `CFITSIO header/library mismatch` warning, which `siril.run_script` filters out of logs. `denoise` also prints `error: no suitable data in src fits` and succeeds, so failure detection (`siril.failed`) looks for `Script execution failed` or `Error in line`, not a bare `error:`.

## Architecture

The tool never processes pixels itself, except for the widget. It classifies frames in Python, generates Siril command scripts, runs `siril-cli`, and keeps each stage's `.ssf` script and `.log` beside its output.

- `classify.py`: stage 1. Reads FITS headers with astropy (never folder names), classifies by `IMAGETYP`, and groups lights by `OBJECT` and `FILTER`. Writes `manifest.json`.
- `background.py`: sky gradient removal, one filter at a time. The image is cut into 96 px blocks (median each); a plane or quadratic is fitted to the darkest 60% of blocks only (iterated, after rejecting textured blocks), so it follows the sky and never models a bright region. A quadratic falls back to a plane when the clean blocks do not cover all four quadrants (it extrapolates wildly otherwise). The level is preserved; only variation is removed. Deliberately conservative: it cannot remove a glow (a glow is also just a bright region; compact ones are indistinguishable from nebulosity) and it partly absorbs very smooth emission that fills half the frame, so a correction over 8 noise sigma prints a warning, and `"background_degree": 0` under override in settings.json switches it off. On the test night it halves the disagreement between filters at the corners (the colour cast once stretched): 1.14 to 0.55 sigma on NGC 7000. Tried and rejected: a residual surface inside the rejection loop (it absorbs anything smooth, including a nebula), and estimating scatter from the survivors (shrinks every pass until nothing is left).
- `hotpixels.py`: finds the sensor's persistent hot pixels from the lights themselves (no darks needed). A hot pixel belongs to the sensor, so it sits at the same pixel in every field while stars move: take the median of several frames per field (cosmic rays vanish), flag isolated spikes (neighbours not raised), and keep pixels flagged in at least two fields; with one field a stricter isolation rule is used. The list (`<out>/hot_pixels.lst`, Siril `P x y H` format, 0-based, y counted from the bottom, so rows are flipped for NINA's `ROWORDER=TOP-DOWN`; checked against a real hot pixel, an off-by-one or a flipped row corrected a different pixel) is applied with `seqcosme` before registration, and in Python for single-frame filters. On the test night: 15,093 pixels (0.17% of the sensor), median excess at those pixels 385 ADU before and 0.5 ADU after. Without dithering they would otherwise stack coherently; they were the source of the coloured specks seen in the widget. `--no-hot-pixel-fix` turns it off.
- `quality.py`: measures every light (star FWHM and roundness by elliptical adaptive moments, star count, noise, sky), judges each frame against its nearest neighbours in time within its group (target, filter, exposure) and rejects clear outliers: soft stars (FWHM x1.2), few stars (x0.75), elongated stars (roundness x0.88; skipped for undersampled stars under 1.8 px). Neighbours, not the whole night, so a slow decline toward dawn is not held against the last frames while a sudden dip stands out; never more than 25% of a group. Results are cached by file (versioned: bump `MEASURE_VERSION` when the measurement changes) and reported in `<out>/frame_quality.json`. Thresholds are overridable per target in settings.json. `--no-reject-frames` turns it off. A circular window makes elongated stars look rounder than they are (a true 0.6 reads 0.77), and the earlier circular numbers (roundness 0.89) were wrong: stars on the test night are about 0.75 round (H, S) and 0.65 (O), and the top-right corner is much worse (FWHM 3.3 px, roundness 0.5).
- `stack.py`: stage 3. One Siril run per target/filter in `<out>/<target>/<filter>/`: `convert`, `register -2pass`, `seqapplyreg -framing=min`, `stack rej w 3 3`. Takes a `Masters` object so calibration frames can slot in. Only the exposure time with the most integration per filter is stacked, unless `--all-exposures` is given.
- `finish.py`: stages 4 to 6. `align` registers the per-filter stacks to each other and crops to the common area, saving `aligned/aligned_<F>.fit`; `background.py` then writes `linear/linear_<F>.fit` (the real, linear output) with each filter's sky gradient removed. `preview` writes autostretched JPGs, a raw-sub "before" image and an SHO (3 filters), HOO (H+O) or RGB (R, G and B filters, matched by role not name order) composite. `_stage()` is the shared runner: it uses a work dir, moves outputs up and skips when the stamp matches.
- `enhance.py` and `starsplit.py`: optional steps that work on layers, not on the whole image. The stars are split from the rest (`starsplit.py`: a classical split (stars detected in each filter separately and the masks combined, so a star strong in only one filter is not left behind as a coloured dot): a star-size band-pass with a size filter (so nebula knots are not mistaken for stars), a three-tier mask whose size grows with star brightness, one mask shared by all filters, and white synthetic noise in the filled regions (correlated noise was tried and looked worse after denoise). Stars on very bright nebulosity are left in the starless layer (`PROTECT_LO`/`PROTECT_HI`, 25 to 40 noise sigma above the sky, smooth transition): a flat fill cannot know the peak it hides. Measured by injecting artificial stars of known brightness onto the real starless layer and comparing the fill with the truth: error at the star centre is under 1 sigma below 10 sigma of nebulosity, 1 to 2 sigma at 10 to 25, but 10 to 19 sigma at 25 to 60 and 38 to 62 at 60+ (the Bubble's core knot, a dimple of 20 to 40%). A local quadratic fit reduced the worst cases only partly (about -55 to -38 sigma) and was worse on faint backgrounds, so it was not adopted. Protection covers about 0.02% of the masked area on the test data and keeps starless + stars exact. Only stars above the threshold are removed, so lowering `DEFAULT_THRESH` trades leftover faint dots against masking more of a crowded field; or StarNet with `--star-splitter starnet`, which needs StarNet set up in Siril and is untested here). `--denoise` runs Siril `denoise` on the starless layer only. `--deconvolve` measures a PSF from the plain stack (`makepsf stars -sym`), then runs `rl -mul -iters=4 -tv -alpha=1000` (iterations from settings) on a non-negative copy of the stars layer; the result is clipped at 0 when recombined, which is what stops RL's negative lobes (dark rings) coming back. `--remove-stars` outputs the starless layer only (and makes `--deconvolve` pointless). Layers are cached in `<target>/layers`; each recombination lands in its own variant folder (`linear+rl+dn`), so the main output and the widget share work. Without deconvolution nothing is clipped, so split + recombine returns the original exactly. Flags affect the main output and Siril previews. The widget always gets the full chain (`final+rl+dn/`: `starless_<F>.fit` and `stars_<F>.fit` kept apart, via `build_layers`); `--no-widget-enhance` builds it from the plain split layers instead. The stars layer is noise-gated (`star_gate` sigmas) before it is used next to denoised starless data, or every former star shows as coloured speckle. Defaults that were tuned on measurements, not taste: 4 RL iterations (a round PSF over-sharpens the short axis of an elongated star and leaves thin streaks; sharpening saturates at ~21% by 4 iterations while roundness loss goes from 13% at 4 to 33% at 10) and a 0.7 denoise blend (fully denoised non-local-means output is a patchwork of curved strokes that a steep stretch makes obvious; 30% natural grain hides it; `-da3d` and `-sos` do not). Do not deconvolve the whole image: that rings badly (0.37% of pixels pushed far below background versus 0.00% with layers), and the default RL gradient-descent step does almost nothing.
- `settings.py`: per-target `settings.json` with an `auto` block (rewritten every run) and an `override` block (yours, never touched). Auto holds what was measured (star FWHM by adaptive Gaussian-window moments on the H stack, sky noise per filter) and the chosen defaults (star threshold, RL iterations, denoise amount, star gate). The effective value is the override if present.
- `widget.py`, `widget_template.html` and `widget_dsp.js`: a self-contained page (palette presets include HSS, an H/S bicolour that needs no O, and RGB for broadband R/G/B filters; with H and S only, HSS is the default) for playing with colour and stretch on layers that were already processed at full resolution, so no heavy processing happens in the browser. Python embeds a ~1000 px block-averaged overview of both layers (starless and stars) and writes full-resolution 512 px tiles of both to `widget_tiles/` as `<script>`-loadable `.js` files (this works from `file://`, while `fetch()` does not). The page: palette presets and per-band filter assignment, nebula stretch (midtones, black point in units of the plain stack's noise from `settings.json`, contrast), colour (saturation, SCNR green removal with an auto-detected amount, channel balance, **colour smoothing**), and stars (asinh stretch with an auto-chosen strength, brightness, colour that fades in with star brightness) screen-blended onto the nebula. Colour smoothing blurs chrominance only; at zoom the full-res luminance is paired with the smoothed overview chroma (LRGB style), which is what hides the colour noise of the weak O and S channels (S/N about 1 at their 99th percentile on the test night). **Frame (rotate + crop) is a live view operation in the widget, not a pipeline setting**: framing is a finishing decision made on the processed image. `widget_dsp.js` holds the pure geometry (`bboxOf`, `fitInside`, `frameGeom`, `frameMatrix`, `viewToImage`; checked against what Siril's `rotate -nocrop` really does, including its output size and clockwise direction). The page composes the frame matrix and the zoom into one CSS transform on the canvas, and the detail layer maps each screen pixel back through zoom and frame to a full-res tile pixel. Rotating auto-fits a crop with no empty corners; in edit mode the image is drawn with a margin (`EDIT_PAD`) so the handles are not clipped by the view edge. Save PNG exports the framed image at overview resolution (a full-res export from the tiles would be the next step). Past ~60% of full resolution the page draws a detail canvas from the tiles. The page must sit next to its `widget_tiles/` folder; the zoom bar says `full-res` or `overview (no tiles)`. A 4 px border is cropped from the layers before building because registration leaves unreliable edge pixels.
- `render.py`: a numpy port of the widget's default look (normalise, midtones stretch with contrast, SCNR with an auto-detected amount, saturation, chroma-only colour smoothing, then the asinh-stretched stars layer screen-blended on top), so the pipeline can produce a picture without a browser. `tests/test_render.py` checks the primitives against `widget_dsp.js` in a real browser, so the two cannot drift apart silently; when you change one, change the other. Layers are bottom-up (Siril), so the image is flipped for display.
- `report.py`: writes `<target>/report.html` (and `draft.jpg`), one self-contained page: before (a raw sub) and after (the draft), the data per filter (frames used and rejected, integration, star size), frame-quality trend charts as inline SVG, the star-size and roundness map across the field in ninths (the sensor-tilt check; Siril stacks are bottom-up so rows are flipped), and what the pipeline did. It only reads what earlier stages wrote (manifest, frame_quality.json, settings.json, hot_pixels.lst, background.json) and never takes the pipeline down: an error becomes a warning.
- `cli.py`: wires the stages together. The widget stage runs inside `finish_target`.
- `siril.py`: finds and runs `siril-cli` and raises on script failure (Siril can exit 0 even when a command failed, so the log is scanned too).

Re-runs skip a stage when its `.stamp` (sha256 of the script plus input path, size and mtime) is unchanged, so editing a generated script or its inputs forces a re-run.

## Gotchas learned on real data

- NINA writes `SNAPSHOT/` frames with `IMAGETYP=LIGHT`. Only `OBJECT == "Snapshot"` marks them, so `frame_from_header` treats those as `other`.
- The filters are named `H`, `O`, `S` (not Ha/OIII/SII). `finish.role()` maps the common spellings.
- Don't name Siril input symlinks the same as the sequence basename. `link f` writes `f_00001.fit`, so inputs are named `in_01.fit` and so on, or they collide.
- Without `-framing=min` on the per-filter registration, frames shifted by different amounts leave thin seams along the edges (a coloured line in the composite). Don't remove it.
- The widget's tiles are quantised with the overview's `vmax`, and the page uses the overview's stats for both layers so the look doesn't change when switching.
- Chrome headless with `--virtual-time-budget` hangs when script files load. For browser checks use Python `playwright` with `channel="chrome"`; `.venv` has it but it isn't a declared dependency.

## Input and utils

The pipeline reads **NINA output only** (one FITS per frame, headers written by NINA). `utils/` holds side tools that are not part of the package or its tests; `utils/unpack_sharpcap.py` converts old SharpCap captures (Siril FITSEQ files, headers stripped) into per-frame FITS with NINA-style headers so they can be used as test data.

## Samples (`samples/`)

One linear stack per filter, from the 2025-02-28 SharpCap night: `ic1805/stack_{H,O,S}.fits` (Heart Nebula, 100 x 18 s each) and `m31/stack_{R,G,B}.fits` (Andromeda, about 50 x 18 s each, stacked with the 18 s master dark). Tile-compressed (RICE_1, 16-bit quantisation: error is 0.007 of the sky noise), about 7.5 MB each; astropy and Siril both read them. They are stacks, so they start the pipeline at align/finish, not at classify. Made by `firstlight` from the unpacked frames (`utils/unpack_sharpcap.py`); the raw frames are not in the repo. They are committed (44 MB in total, so avoid replacing them often: every version stays in git history).

## Dark library (`calibration.py`)
- Masters live in `~/.firstlight/library` (override with `--library` or `$FIRSTLIGHT_LIBRARY`), indexed by `index.json`. Darks found in a night folder are grouped by instrument/binning/gain/offset/exposure, then clustered by sensor temperature, and built with `stack dark rej w 3 3 -nonorm`; unchanged source frames are not rebuilt.
- A master matches lights on instrument, binning, gain and offset exactly, on exposure within 0.5 s (`EXPOSURE_TOLERANCE`; SharpCap's 18.08 s lights against 18 s darks), and on temperature within `dark_temp_tolerance` (1.5 C). With a match, `stack_filter` calibrates with `-dark= -cc=dark` and skips the hot-pixel list; without one it says why and falls back to the list. `--no-darks` disables both. Flats stay optional and unimplemented.
- `firstlight-library list|add <folder>|check <folder>` manages it. Missing header values (e.g. no XBINNING) count as compatible.

## Desktop app (`app.py`, `app_ui.html`, `packaging/`)
- `firstlight-app` (needs `pip install -e '.[app]'`) opens a pywebview window over `app_ui.html`: folder pickers, a scan summary, options, live log, links to each target's widget/report, and the dark library. `Backend` is plain Python and tested without a window; a run is `cli.main` on a thread with stdout/stderr captured line by line and polled by the page (one run at a time, no cancel yet). Results open in the default browser via `open`.
- `packaging/build_app.sh` builds `dist/firstlight.app` with PyInstaller (~60 MB; unsigned, so right-click, Open the first time; Siril is not bundled, `siril.find_siril` also checks Homebrew's bin because Finder-launched apps have a minimal PATH). `packaging/hooks/hook-astropy.py` replaces the stock hook, which imports every astropy submodule and dies on the optional matplotlib one; it must also ship astropy's `*parsetab.py` or unit parsing fails inside FITS headers (silently classified as unreadable). Check a build with `FIRSTLIGHT_SELFTEST=<night folder> dist/firstlight.app/Contents/MacOS/firstlight`: it imports every module, scans and dry-runs without a window.
